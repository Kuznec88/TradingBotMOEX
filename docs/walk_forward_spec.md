# Walk-forward на уровне сделок (реализовано в pipeline)

## Что это

Разбиение **хронологически отсортированных** сделок на **K непрерывных бакетов с почти равным числом сделок** и расчёт `aggregate_sample_metrics` по каждому бакету. Это **не** полноценный walk-forward по барам (для него нужен повторный бэктест на каждом окне OHLCV); зато даёт **стабильность знака expectancy / PF во времени** без lookahead.

## Параметры

| Параметр | Значение по умолчанию | Смысл |
|----------|------------------------|--------|
| `n_buckets` (CLI `--walk-forward-buckets`) | `0` = выкл. | Число бакетов (рекомендуется 3–6 при n≥30). |

## Интерпретация

- Если метрики **ломаются** только в последнем бакете — возможен режимный сдиг на хвосте выборки.
- Если **все** бакеты отрицательны — проблема не «хвост», а стратегия/косты/данные.
- При **n < K** сделок блок в `pnl_estimate.json` будет пустым или с `note`.
